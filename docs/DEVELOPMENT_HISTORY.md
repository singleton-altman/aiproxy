# AI Proxy Mobile 开发历程

- 更新时间：2026-07-28
- 代码仓库：`xiaojun5270/aiproxy`
- 技术栈：Expo、React Native、Expo Router、TypeScript
- 版本起点：`0.0.1`

本文记录 AI Proxy 移动管理端已经交付的产品里程碑与工程演进。内容聚焦功能建设、架构设计、质量保障和发布能力。

## 1. 项目定位

AI Proxy Mobile 是 AI Proxy Service 的 iOS 与 Android 管理客户端，目标是让用户和管理员在移动设备上完成日常操作：

1. 用户可以管理凭证、模型和用量，并直接调用聊天与图片生成能力。
2. 管理员可以维护用户、套餐、上游账号、供应商、模型、额度、统计和系统配置。
3. App 与 Web 管理端共享同一套服务端契约和权限模型。
4. 页面针对手机交互设计，完整支持安全区、键盘、弹层和长列表。
5. 项目具备可重复验证、自动构建和可追溯发布能力。

## 3. 工程演进

### 接口治理

`docs/AIProxy_API_Endpoints.json` 是接口目录的结构化数据源，`src/api/endpoints.generated.ts` 由脚本生成。接口文档、服务封装和调试页面均以同一份注册表为基础，降低定义漂移风险。

### 认证与会话

应用支持 Cookie Session、API Key 和管理令牌。认证类型、服务地址和凭证状态由会话层统一维护，API 客户端负责请求头、Cookie、超时、错误解析和认证失效处理。

### 数据访问

业务请求集中在 `src/services/`，页面通过 TanStack Query 使用服务层。响应归一化集中处理常见分页、列表和嵌套数据结构，页面只消费稳定的数据模型。

### 组件体系

页面框架、资源列表、结构化表单、状态反馈、API Key 选择器和弹层行为均采用共享组件。管理页面保持一致交互，同时允许复杂模块使用专用表单和列表。

### AI 网关

网关层独立处理 API Key 认证、模型目录、SSE 流式响应、Anthropic 消息协议、OpenAI Responses API 和图片生成请求，避免与管理 API 的 Session 逻辑耦合。

### 发布流程

GitHub Actions 提供 Android APK 和 iOS 无证书 IPA 两类本地原生构建工作流。正式包不集成 Expo Dev Client 或 Expo OTA Updates；构建使用锁定依赖，产物文件名包含应用版本，并与对应 Git 提交关联，便于安装验证和问题追踪。

## 4. 质量基线

每次接口或依赖变更后执行：

```bash
npm ci
npm run verify
```

`npm run verify` 包含以下检查：

1. Expo、npm、锁文件、原生构建号与版本记录保持一致。
2. 接口注册表与生成文件同步。
3. TypeScript 类型检查。
4. Node 接口契约测试。
5. npm 依赖漏洞审计。

移动端发布前还需要分别验证 iOS 与 Android Bundle，并检查登录、导航、键盘、弹层、长列表、聊天和图片生成等关键流程。

## 5. 版本策略

项目采用语义化版本，版本序列从 `0.0.1` 开始：

- 日常功能、修复和界面优化递增补丁版本，例如 `0.0.1` 到 `0.0.2`。
- 一组较大的兼容功能递增次版本，例如 `0.0.9` 到 `0.1.0`。
- 达到稳定发布标准后递增主版本，例如 `0.9.0` 到 `1.0.0`。
- 每次版本递增同时增加 iOS Build Number 和 Android Version Code。
- 每个发布版本必须在 `CHANGELOG.md` 中记录用户可感知的变化。
- 日常开发期间保持当前版本不变，新增内容记录在 `CHANGELOG.md` 的 `Unreleased`。

只有收到明确的推送或发布指令后，才在推送前执行 `npm run version:bump`。该命令可默认递增补丁版本，也可以传入 `minor`、`major` 或指定版本号；版本一致性由 `npm run verify` 自动检查。

## 6. 目录职责

- `app/`：Expo Router 页面、标签导航和管理模块。
- `src/services/`：认证、用户、管理端和 AI 网关服务。
- `src/lib/api.ts`：统一 API 客户端。
- `src/store/session.ts`：认证模式与会话状态。
- `src/components/`：页面框架、资源组件、表单和共享交互组件。
- `scripts/version.mjs`：版本同步、构建号递增和一致性检查。
- `docs/`：接口说明、接口注册表和项目文档。
- `CHANGELOG.md`：发布版本的重要变更记录。
- `tests/`：接口契约与自动化检查。
- `.github/workflows/`：移动端构建与发布工作流。

## 7. 维护规范

1. 日常开发只更新 `CHANGELOG.md` 的 `Unreleased`；明确推送或发布时，才在推送前递增版本并整理版本记录。
2. 接口变更先更新注册表，再生成类型文件并运行完整验证。
3. 接口路径、HTTP 方法和 Payload 以当前服务端契约为准。
4. 页面、服务、注册表和文档必须在同一次变更中保持同步。
5. 编辑类功能需要覆盖加载、校验、保存、删除和错误反馈。
6. UI 变更需要同时验证小屏、宽屏、键盘、弹层、长列表和安全区。
7. 发布产物必须能够追溯到已通过验证的 Git 提交。
